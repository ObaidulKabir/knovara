Data Flow Diagrams

Gane–Sarson notation: rounded boxes are processes, sharp-cornered boxes are external entities, open two-line shapes are data stores, and every arrow carries the data actually moving, not just a "related to" line.

Level 0 — Context Diagram

The whole system as a single process, bounded by the four parties it exchanges data with. Model providers are outside the boundary: the system sends them text and gets back summaries, vectors and relevance scores.

Level 1 — System Decomposition

Six processes in three rows: ingest/index (write path), retrieve/deliver (read path), and memory/metrics (support path). The AI Agent / Caller is drawn four times and Model Providers twice — the same entity each time, placed next to each process it actually talks to, so no flow has to cross the whole page.

Reading the two levels together: Level 0 is the promise made to the outside world — hand over a source or a question, get back a context package or an ack. Level 1 is how that promise is kept: two processes that only run when a source is new or changed (1.0, 2.0), two that run on every question (3.0, 4.0), and two supporting processes that make the first four cheaper over time (5.0, 6.0). The stores map directly onto infra/postgres/init.sql (D1/D2) and the ICE.ContextMemory / ICE.Evaluation services (D3/D4).
