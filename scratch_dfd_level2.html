Level 2 — Six Subsystems

Each Level 1 process opened up into its own sub-processes. Every diagram's external edges are exactly what Level 1 already showed entering and leaving that process — nothing new crosses the boundary, only the inside gets more detailed. Dashed, muted boxes are boundary references (another process, a store, an external entity); solid boxes are decomposed here.

1.0 Ingest & Represent 2.0 Multi-Index 3.0 Retrieve & Rank 4.0 Optimize & Deliver 5.0 Context Memory 6.0 Metrics

Decomposes process 1.0

Ingest & Represent Source

Splits into the two services that back it: ingestion authorizes the caller, registers the resource once per (tenant, URI) and stops if the version is unchanged; representation turns new structure into the hierarchy other processes consume.

Decomposes process 2.0

Manage Multi-Index Store

One entry point checks whether a resource is already indexed and clears stale entries before the four index types are written in parallel.

Decomposes process 3.0

Retrieve & Rank Evidence

The evidence cache is checked before any index search, keyed by tenant, normalized question and index version. Past that, retrieval escalates only as far as the sufficiency check requires, and nothing leaves until 3.6 has re-read each cited passage at its current version.

Decomposes process 4.0

Optimize & Deliver Context

A short, linear pipeline: thin the evidence down, fit it to budget, package it with citations, and report what that cost.

Decomposes process 5.0

Manage Context Memory

Three independent lanes, one per cache. 5.1 builds the two version-sensitive keys; session knowledge is looked up by tenant and session id and needs neither a resource nor a version.

Decomposes process 6.0

Record & Report Metrics

Writing and reading metrics are independent paths that only meet at the store; recording a task's metrics never waits on, or blocks, a dashboard query.
