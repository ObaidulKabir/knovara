Knovara — Services & Consumption

The other diagrams show what happens inside the engine. This one shows what runs around it and who talks to what: first as it stands today, then as decided in ADR-001 — agents as the front door, the engine running locally by default, and the control plane as one customer's authority domain.

Today: a server stack with a SaaS control plane beside it

Every way in currently needs the Docker stack (about 4.8 GB measured) or a running server. The control plane issues credentials; the API only verifies them. Highlighted flows are where a credential is missing once API authentication is switched on.

Target (ADR-001): one engine, four ways to run it

The same engine is delivered in four forms. The local runtime is the default and the front door for agents; team and managed servers are what customers pay for; the hybrid form lets a local runtime attach to a server when it needs to share knowledge or borrow compute. The control plane is optional for the first and central to the others.

Business mapping: A, and B when a team self-hosts it, are the free Community tier; C, where we host the authority domain, is Team (hosted); the governance modules (SSO/SCIM, audit retention, policy, federation) are Enterprise, on a customer-run or hosted domain; the compute we run for C and D is Managed compute. Decisions and open items are in business_architecture.md and system_architecture.md (ADR-001).
