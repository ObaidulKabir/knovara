Knovara — Architecture

Two paths that run at different times. Ingestion runs once per source version and stops early if the source hasn't changed. Questions run on their own path, starting at retrieval, and skip searching altogether when an equivalent question's evidence is still current.

Two paths, two stores, two savings

Stages 1–4 never run for a question. The ingest path fills a durable store; the query path reads from it and keeps a disposable cache of what it found. The two accent arrows are where repeated work is avoided.

Inside stage 5: retrieval is progressive, not uniform

The cache is checked before any search. On a miss, search escalates only as far as the sufficiency check requires; expansion runs only when targeted retrieval wasn't enough. Everything is verified before it leaves.

Reading the two figures together: the first shows where repeated work is avoided — an unchanged source isn't reprocessed, and a still-valid answer isn't re-searched. The second shows why a single new question costs no more than it needs to. Stage 7 is the consumer's own model: Knovara returns cited evidence and never writes answers.
