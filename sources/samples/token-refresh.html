Authentication Handbook

Access Tokens

Access tokens are short-lived JSON Web Tokens issued by the identity service. Each token expires fifteen minutes after it is issued.

Token Refresh Mechanism

The system issues a new access token when the existing token expires. The client presents its refresh token to the token endpoint, which validates it, rotates it, and returns a fresh access token together with a new refresh token.

A refresh token can be used exactly once. Presenting an already-used refresh token revokes the whole token family, which protects against stolen refresh tokens being replayed. Refresh tokens themselves expire after thirty days of inactivity, after which the user must sign in again. Clients should refresh proactively about one minute before the access token expires, so requests in flight are not rejected. If the token endpoint is unreachable, clients should retry with backoff rather than discarding the session, because the refresh token stays valid until it is used or expires. Servers validate the signature, issuer, audience and expiry of every access token on every request; no token is trusted because it was valid earlier.
